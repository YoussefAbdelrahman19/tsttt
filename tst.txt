1. Generative AI Client or Project

I used generative AI as a support tool in a security automation project. The project was about building a Logic App flow to improve the vulnerability ticketing process. The main goal was to group vulnerability findings based on the device group, then automatically open a Jira ticket and assign it to the correct responsible team. I used AI mainly to help me design the flow, think about the order of the actions, conditions, grouping logic, loops, and different ways to handle the ticket creation and assignment. It also helped me when I was troubleshooting the flow or comparing different design options. I used it as a technical assistant to support the design, while I was still responsible for implementing, testing, and validating the final automation.

3. Application, Work Product, or Deliverable

I created different security work products where generative AI helped me during the design, development, and validation process.

One of the main examples was a Logic App automation for vulnerability management. The flow was designed to group vulnerability findings based on the device group, automatically create Jira tickets, and assign each ticket to the correct responsible team. I used AI to help me think about the flow design, grouping logic, conditions, loops, ticket creation, assignment logic, and different ways to handle errors or missing values. It helped me compare different implementation options and troubleshoot parts of the flow during development.

I also used AI in detection engineering. I used it to help me create and improve KQL queries for Microsoft Sentinel and Defender XDR. I normally start by defining the use case, what behaviour I want to detect, and what data sources are available. Then I use AI to help me think about the query structure, filtering, correlation, joins, and different ways to detect the same behaviour.

After that, I always validate and test the KQL myself. I check if the tables and fields are correct, if the joins and time windows make sense, if the logic is too broad, and if the query is creating too many false positives. I also test the query in the real security platform and review the results before considering it ready.

Another important work product was a MITRE ATT&CK gap analysis. I reviewed the current detection coverage, mapped detections to techniques and sub-techniques, and looked for areas where the coverage was missing or weak. AI helped me organise the analysis and think about new detection use cases for the gaps.

For new use cases, AI also helped me think about the attack behaviour, required data source, useful events, detection conditions, possible false positives, and how the use case should be tested.

The final work products included the Logic App automation design, Jira ticketing flow, KQL detections, improved existing queries, MITRE ATT&CK gap analysis, new security use cases, testing steps, and technical documentation. AI helped me work faster and look at different options, but I always did the final testing and validation myself.

4. Approach, Methods, and Tools

My approach is normally simple and practical. I first understand the problem and define what I want to achieve. For automation, I map the process first, then use AI to help me design the Logic App flow, conditions, grouping logic, and ticket assignment. For detections, I start with the use case, attack behaviour, and available data sources. Then I use AI to help me improve the KQL logic or think about better correlation options. I do not use the first result directly. I review it, test it in Sentinel or Defender XDR, check the tables, fields, joins, filters, time range, and results, then improve it if needed. I used Microsoft Sentinel, Defender XDR, Entra ID, KQL, Logic Apps, Jira, Azure security services, and MITRE ATT&CK.

5. Management of Risks and AI Ethical Concerns

I always treat AI output as a suggestion and not as a final answer. In security work, AI can give wrong technical details, for example a wrong KQL field, table, join, or detection logic. Because of this, I always validate the output myself. I test KQL in Sentinel or Defender XDR, review the results, and check if the detection is really matching the expected behaviour. For MITRE mapping, I check that the technique really matches the use case. For automation, I test the conditions, grouping logic, ticket creation, and assignment before using the flow. I also keep human control for important security decisions. AI can support the work, but it should not make high-impact decisions by itself. My approach is to use AI for support, test the result, validate it, and keep the final decision with the engineer.
